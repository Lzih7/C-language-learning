# Software_SPI 项目分析文档

## 项目概述

本项目实现了基于STM32F103的软件SPI通信，用于控制W25Q64闪存芯片。通过GPIO模拟SPI时序，实现对外部存储器的读写操作。

## 基本知识点

### 1. SPI通信协议

**SPI (Serial Peripheral Interface)** 是一种同步串行通信接口，具有以下特点：

- **四线制通信**：
  - `SS/CS` (Slave Select/Chip Select)：片选信号，低电平有效
  - `SCK` (Serial Clock)：时钟信号，由主设备产生
  - `MOSI` (Master Out Slave In)：主设备输出，从设备输入
  - `MISO` (Master In Slave Out)：主设备输入，从设备输出

- **通信模式**：本项目采用模式0
  - CPOL = 0：时钟空闲时为低电平
  - CPHA = 0：数据在时钟上升沿采样

### 2. 引脚配置

```c
// GPIO引脚分配
PA4 -> SS   (片选信号)
PA5 -> SCK  (时钟信号)
PA6 -> MISO (主入从出)
PA7 -> MOSI (主出从入)
```

### 3. W25Q64闪存芯片

- **容量**：64Mbit (8MB)
- **页大小**：256字节
- **扇区大小**：4KB
- **块大小**：64KB
- **擦写次数**：>100,000次

## 核心算法流程

### 1. 软件SPI初始化流程

```
开始
  ↓
使能GPIOA时钟
  ↓
配置GPIO引脚模式
├─ PA4,PA5,PA7 → 推挽输出 50MHz
└─ PA6 → 上拉输入 50MHz
  ↓
设置初始状态
├─ SS = 1 (不选中从设备)
└─ SCK = 0 (时钟初始低电平)
  ↓
结束
```

### 2. SPI字节交换算法

```
MySPI_SwapByte(ByteSend):
  ↓
初始化接收字节 = 0x00
  ↓
循环8次 (i = 0 to 7):
  ├─ 设置MOSI = ByteSend的第i位 (从高位开始)
  ├─ SCK = 1 (上升沿，从设备读取数据)
  ├─ 读取MISO状态
  │   └─ 如果MISO = 1，设置接收字节的第i位
  └─ SCK = 0 (下降沿，准备下一位)
  ↓
返回接收字节
```

### 3. W25Q64操作流程

#### 3.1 读取ID流程

```
W25Q64_ReadID():
  ↓
拉低SS (开始通信)
  ↓
发送JEDEC_ID指令 (0x9F)
  ↓
接收厂商ID (1字节)
  ↓
接收设备ID (2字节)
  ↓
拉高SS (结束通信)
```

#### 3.2 页编程流程

```
W25Q64_PageProgram():
  ↓
执行写使能 (0x06指令)
  ↓
拉低SS
  ↓
发送页编程指令 (0x02)
  ↓
发送24位地址
├─ 地址[23:16]
├─ 地址[15:8]
└─ 地址[7:0]
  ↓
循环发送数据字节
  ↓
拉高SS
  ↓
等待编程完成 (检查忙状态)
```

#### 3.3 扇区擦除流程

```
W25Q64_SectorErase():
  ↓
执行写使能 (0x06指令)
  ↓
拉低SS
  ↓
发送扇区擦除指令 (0x20)
  ↓
发送24位地址
  ↓
拉高SS
  ↓
等待擦除完成 (检查忙状态)
```

#### 3.4 数据读取流程

```
W25Q64_ReadData():
  ↓
拉低SS
  ↓
发送读数据指令 (0x03)
  ↓
发送24位地址
  ↓
循环接收数据字节
  ↓
拉高SS
```

### 4. 忙状态检测算法

```
W25Q64_WaitBusy():
  ↓
拉低SS
  ↓
发送读状态寄存器指令 (0x05)
  ↓
循环读取状态字节
  ├─ 检查BUSY位 (bit 0)
  ├─ 如果BUSY = 1，继续等待
  └─ 如果BUSY = 0，操作完成
  ↓
拉高SS
```

## 关键技术要点

### 1. 时序控制

- **模式0时序**：数据在SCK上升沿有效，下降沿准备
- **位序**：MSB优先传输 (从高位到低位)
- **片选控制**：通信期间SS保持低电平

### 2. 数据处理

- **地址分解**：24位地址分成3个8位字节传输
- **数据缓冲**：使用数组进行批量数据操作
- **状态检测**：通过状态寄存器监控操作完成

### 3. 错误处理

- **超时机制**：忙等待中加入超时计数器
- **写保护**：操作前必须执行写使能指令
- **地址对齐**：页编程不能跨页边界

## 优缺点分析

### 优点

1. **灵活性高**：可使用任意GPIO引脚
2. **资源占用少**：不占用硬件SPI外设
3. **易于调试**：时序可控，便于分析
4. **成本低**：无需额外硬件资源

### 缺点

1. **速度较慢**：受CPU执行速度限制
2. **占用CPU资源**：需要软件控制每个时钟周期
3. **实时性差**：可能被中断打断影响时序
4. **功耗较高**：CPU需要持续工作

## 应用场景

- 硬件SPI资源不足时的替代方案
- 需要多个SPI设备但引脚有限
- 对通信速度要求不高的场合
- 学习和理解SPI协议原理
